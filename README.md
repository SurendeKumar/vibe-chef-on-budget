# 🍽️ Vibe Chef on a Budget

Tell it your **mood** and your **budget** — it tells you what to eat, with
an estimated cost per meal.

> Stripe project name: `mood-meal` (backend identifier only — see
> [Project naming](#project-naming) below).

## Tech stack

| Layer | Technology |
|---|---|
| Framework | [Next.js 15](https://nextjs.org) (App Router) + TypeScript |
| Styling | [Tailwind CSS](https://tailwindcss.com) |
| AI / recommendations | [OpenRouter](https://openrouter.ai) (free tier) — see [models used](#ai-models-used) |
| Database | [Supabase](https://supabase.com) Postgres (free tier), accessed directly via [`pg`](https://node-postgres.com) |
| Provisioning | [Stripe Projects CLI](https://docs.stripe.com/projects) (`stripe projects`) |
| Hosting (planned) | [Vercel](https://vercel.com) (free tier) |

## AI models used

Recommendations are generated by calling OpenRouter's chat completions API.
`lib/openrouter.ts` tries free models in this order and falls back to the
next one if a model is unavailable or rate-limited (OpenRouter's free
catalog changes often):

1. `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`
2. `baidu/ernie-5.5-flash-preview:free`
3. `liquid/lfm-2.5-2.6b:free`
4. `google/gemma-4-31b-it:free`
5. `google/gemma-4-26b-a4b-it:free`

If every model call fails (e.g. offline, no API key), a small built-in
fallback table in the same file returns a sensible meal per mood so the app
never shows an empty result.

## Getting started

```bash
# 1. Install dependencies
npm install

# 2. Sync Stripe Projects credentials into .env (gitignored)
stripe projects env --pull

# 3. (Optional) Create the database schema — see Known issues below
npm run db:migrate

# 4. Run the dev server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

Other scripts:

```bash
npm run build        # production build
npm run start         # run the production build
npm run lint          # lint
npm run db:migrate     # (re)apply sql/schema.sql to Supabase
```

## How it works

1. Pick a mood (10 options), set a budget per meal with the slider, and
   optionally type what you're craving.
2. `POST /api/recommend` builds a structured-JSON prompt from your mood,
   budget, and cravings, calls OpenRouter, and returns 3 meals — each with a
   name, cuisine, description, estimated cost, and a short explanation of
   why it matches your mood.
3. Each suggestion is (best-effort) persisted to the Supabase
   `recommendations` table so it can be marked as a favorite
   (`PATCH /api/favorites`) and listed later (`GET /api/favorites`).

## Project structure

```
app/
  page.tsx                 # main UI (mood picker, budget slider, results)
  api/recommend/route.ts   # calls OpenRouter, persists to Supabase
  api/favorites/route.ts   # list / toggle favorites
components/                # MoodPicker, BudgetSlider, MealCard
lib/
  openrouter.ts            # model list, prompt, fallback meals
  db.ts                    # Postgres pool (Supabase)
  types.ts                 # shared types (Mood, Meal, ...)
sql/schema.sql              # recommendations table
scripts/migrate.mjs         # applies sql/schema.sql
```

## Known issues

- **Supabase DB auth**: direct Postgres connections to the provisioned
  Supabase project currently fail with `password authentication failed`,
  even after rotating credentials (`stripe projects rotate mood-meal-db`).
  This looks like a provider-side sync issue between Stripe Projects and
  Supabase. **It doesn't block the app** — recommendations still work fully,
  they just won't persist/favorite until this is resolved. Run
  `npm run db:migrate` to retry once it's fixed.

The Stripe Projects CLI locks a project's name at `stripe projects init`
time — there's no rename command. The backend project is named `mood-meal`,
but the app itself is branded "Vibe Chef on a Budget" everywhere a user
would actually see it (this README, `package.json`, the UI).
